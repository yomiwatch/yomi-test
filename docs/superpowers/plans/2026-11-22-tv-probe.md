# TV Probe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure on the real Titan OS TV what the browser can do (codecs, HDR, HLS playback, key codes) and whether a public https page is allowed to reach a Yomi-like server on the home network, so that the build plans for server, app and pairing service rest on facts.

**Architecture:** A static test page (`probe/page/`) runs all measurements automatically and shows the results in large type on the screen. A small Node server (`probe/server/`) on the Mac or Unraid PC in the home network serves test videos and a ping endpoint, and receives the report. The server uses the public wildcard certificate of `local-ip.sh`, so that `https://<ip-with-dashes>.local-ip.sh:8443` has a valid certificate and points to a private IP — exactly the situation of Yomi Connect.

**Tech Stack:** Node 24 (built-in TypeScript type stripping and `node:test`, no npm runtime dependencies for the server), plain ES modules in the browser, hls.js 1.5.17 via jsDelivr, ffmpeg 9 (libx264, libx265, aac, ac3, eac3) for test media.

**Spec:** `/Users/jesse/dev/yomi/yomi-server/docs/superpowers/specs/2026-11-21-yomi-design.md` (sections "First step: test on the real TV" ("Eerste stap: test op de echte tv"), "Constraints" ("Randvoorwaarden"), "3. Pairing service" ("3. Koppeldienst")).

## Global Constraints

- Everything for the probe lives in `yomi-test/probe/`; it is measurement tooling, not production code of the app.
- Node version: 24 or higher (`node --test`, `.ts` files directly executable).
- Server ports: https `8443`, http `8080`.
- Hostname of the test server: `<ip with dashes>.local-ip.sh`, e.g. `192-168-2-6.local-ip.sh`. Certificate: `https://local-ip.sh/server.pem` and `https://local-ip.sh/server.key` (public, for testing only; local-ip.sh no longer provides a certificate since 2026).
- The page gets the server address via the query parameter `?server=192-168-1-20`.
- hls.js exactly: `https://cdn.jsdelivr.net/npm/hls.js@1.5.17/dist/hls.min.js`.
- Page text in English, at least 24px, readable from the couch; everything works without a mouse (measurements start by themselves).
- Reports are saved in `probe/results/` and committed.
- Every measurement has a timeout; one hanging measurement must not hold up the rest.

## Review Focus

- **TV cannot reach the LAN server** (wrong IP, firewall, router blocks DNS to private IP): the page must still show the codec and HDR results on screen and clearly report "Report not sent", not hang. → Task 2 (`network.test.ts`: fetch that fails) and Task 6 (manual check without server).
- **hls.js does not load** (CDN blocked/offline): playback tests report "hls.js not loaded" and try native HLS (`canPlayType('application/vnd.apple.mpegurl')`). → Task 6.
- **A video that never fires `playing` or `error`**: at most 15 s per stream, then "timeout" and on to the next. → Task 2 (`withTimeout`).
- **Report too large or not valid JSON**: server responds `413` above 1 MB and `400` on invalid JSON/shape, and writes nothing. → Task 5.
- **PNA/LNA preflight**: Chromium may send an `OPTIONS` preflight with `Access-Control-Request-Private-Network: true`; the server must answer it with `Access-Control-Allow-Private-Network: true` and record *that* it came (that is a measurement result). → Task 5.

### Task 5: Probe server

**Files:**
- Create: `probe/server/server.ts`, `probe/certs/fetch-cert.sh`
- Test: `probe/test/server.test.ts`

**Interfaces:**
- Consumes: `validateReport`, `fileName` (Task 3).
- Produces: `export function createHandler(options: { mediaDir: string, pageDir: string, resultsDir: string }): (req: IncomingMessage, res: ServerResponse) => void` and a `main()` that, when run directly, starts https on `8443` (certs from `probe/certs/fullchain.pem`, `privkey.pem`) and http on `8080` with the same handler and logs the URLs.

Handler behaviour:
- Every response: `Access-Control-Allow-Origin: <Origin of the request or *>`, `Vary: Origin`.
- `OPTIONS *`: `204` with `Access-Control-Allow-Methods: GET, POST, OPTIONS`, `Access-Control-Allow-Headers: content-type`, `Access-Control-Max-Age: 0`, and if the request has `Access-Control-Request-Private-Network: true`: `Access-Control-Allow-Private-Network: true`. Set `pnaSeen = true` in memory.
- `GET /ping` → `200` JSON `{ "ok": true, "pnaSeen": <boolean> }`.
- `GET /media/...` → files from `mediaDir` (`.m3u8` → `application/vnd.apple.mpegurl`, `.mp4` → `video/mp4`, `.m4s` → `video/iso.segment`); path traversal (`..`) → `404`.
- `GET /page/...` → files from `pageDir` (so the page can also be loaded from the LAN).
- `POST /report` → body max 1 048 576 bytes, otherwise `413`; not JSON or `validateReport` returns `null` → `400`; otherwise write `{...report, pnaSeen}` to `resultsDir/fileName(new Date(), report.ua)` and respond `201` `{ "saved": "<fileName>" }`.

`fetch-cert.sh`: download `https://local-ip.sh/fullchain.pem` and `https://local-ip.sh/privkey.pem` to `probe/certs/`.

### Task 6: Test page

**Files:**
- Create: `probe/page/index.html`, `probe/page/probe.js`, `probe/page/ok.txt` (content `ok`)

**Interfaces:**
- Consumes: `CODEC_CASES`, `measureCodecs`, `measureCapabilities` (Task 1); `withTimeout`, `serverAddresses`, `measureNetwork` (Task 2); server endpoints (Task 5).

Behaviour (`probe.js`, starts on `DOMContentLoaded`, everything automatic, fixed order):
1. **Device:** `navigator.userAgent`, `screen.width×height`, `devicePixelRatio`, `innerWidth×innerHeight`, `matchMedia('(dynamic-range: high)').matches`, `matchMedia('(video-dynamic-range: high)').matches`.
2. **Codecs:** `measureCodecs(MediaSource.isTypeSupported)` (if `MediaSource` does not exist → everything `false` with the message "No MediaSource").
3. **Capabilities:** `measureCapabilities(c => navigator.mediaCapabilities.decodingInfo(c))` (if the API is missing → message).
4. **Network:** `measureNetwork(serverAddresses(param), fetch)`; without a valid `?server=` → the section shows "No server specified (?server=192-168-1-20)".
5. **Playback:** for each of the five variants from Task 4, source `${https}/media/<name>/index.m3u8`: native HLS if `video.canPlayType('application/vnd.apple.mpegurl')` is not empty, otherwise hls.js (if the script does not load → result "hls.js not loaded"). Passed = `playing` and `currentTime > 2` within `withTimeout(…, 15000, name)`. Record: `ok`, `videoWidth×videoHeight`, `method` (`native`/`hls.js`), `error`. Videos 480×270 on screen, muted, stopped and removed after the measurement.
6. **Report:** `POST ${https}/report` with `{ version: 1, ua, time: new Date().toISOString(), device, codecs, capabilities, network, playback, keys }`; result on screen: "Report saved as …" or "Report not sent: <error>".
7. **Keys:** a section that shows the last 12 `keydown` events (`key`, `code`, `keyCode`) with the instruction "Press: arrows, OK, Play/Pause, Red, Green, Yellow, Blue, Info, Back". After each key the report is sent again (the same file name within the same minute overwrites). `preventDefault()` only for the arrows.

Layout: black background, white text ≥ 24px, a heading per section, one line per measurement with ✓ (green) or ✗ (red) — with text, not just colour.
